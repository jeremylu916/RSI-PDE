Recursive self-improvement on scientific code

Can a self-improving agent write PDE solvers that generalize?

RSI-PDE Bench gives a self-improvement harness one foundation model, a fixed budget and a set of identify-then-solve PDE cases. The harness must turn feedback into a solver program. That solver is then scored, after every round, on a hidden test split that no run ever sees.

What it measures

Each case gives 256 noisy samples (1 % RMS noise) of an unknown equation from a class library, together with black-box forcing, initial and boundary data. The solver must identify the class and its coefficients, then solve on the whole domain. To pass, a case needs a space-time and final-time relative L2 error of at most 2e-3, exact initial and boundary data (to 1e-10), and a solve within its time limit.

HEADLINE 1

Held-out pass rate

The share of hidden-test cases passed by the solver the harness retained after N rounds. A round is one gated validation submission.

HEADLINE 2

Gain over a single run

The held-out pass rate minus that of a single-run entrant with the same model: one model call, frozen as returned. This is what the self-improvement loop adds.

HEADLINE 3

Dev–test gap

The validation pass rate minus the held-out pass rate of the same solver. A large gap means the loop overfit to the cases it could see.

How a run works

The entrant is a harness: this project's RSI loop, Claude Code, Codex, or your own. It works in a sandbox with the public cases and one fixed model. Every model call goes through a metering proxy, which holds the only credential and enforces the budget.

The budget

The caps sit above what 24 matched 2-hour runs used, so a run is limited by time and validation submissions. They bind only a harness that uses far more. The acceptance gate requires all of: the macro relative L2 drops by more than 0.5 %; no class loses passes or rises by more than 5 %; no case rises by more than 25 %; and every case executes.

Tracks

There are three tracks with 42 problem templates. Every template appears once in training, once in validation and five times in the hidden test. The numbers come from a seeded generator, so the three splits share one distribution.

Calibration

Before any model was run, fixed solvers from earlier 2-hour runs solved all 1001 cases of the expanded release: 2,856 sandboxed solves, with no model calls. The probes separate clearly. Templates that every strong probe solved were hardened for the benchmark.

Get started

Clone the repository and build the environment. Run your harness, or one of the built-in entrants, on a GPU node with bubblewrap. The maintainers score submissions on the hidden test.

git clone https://github.com/jeremylu916/RSI-PDE.git && cd RSI-PDE
pip install -e .
export PDE_RSI_PROJECT_ROOT=$PWD   # the code defaults to the original cluster path
# score a solver on a public split (training or validation)
rsi-pde-bench-eval solver.py --track tex --split bench-val
# run a built-in entrant: harness v2, Claude Code or Codex
python scripts/bench.py run --track tex --entrant pde-rsi-v2 --model opus55 --cores 0,1 --output runs/bench-v1-tex-...
# maintainers: score every round on the hidden test, then build the table
python scripts/bench.py score --runs runs/bench-v1-* --cores 2,3,4,5
python scripts/bench.py report
