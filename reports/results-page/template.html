PDE-RSI Benchmark Results

Each agent identifies an unknown PDE from 256 noisy samples and writes a solver. This page compares a single model request, your RSI harness (v1 and v2), and the native coding agents (Claude Code with Opus 5.5, Codex with GPT-5.5). Every model runs with the same task, evaluator, sandbox and budget. The second half lists every benchmark equation, split and setting.

Why the strict Opus single run scores 0 on the inventory suite

The inventory suite asks one answer to identify and solve 12 very different families, from 1-D Burgers to a 4-D elliptic problem. Every strict Opus answer was rejected before any code ran, and a rejected single run keeps the empty starting program, which fails every case:

  • At the 64k-token output cap, all six answers (v1 and v2) were cut off while still writing.
  • At Opus 5.5's own 128k maximum, the v1 answers finished, but their programs had 29,137–32,261 characters. All but one broke the 30,000-character limit that every configuration has. The one under the limit, and one over it, also used import time, which the sandbox bans.
  • Under v2, one answer must write a separate part for every class. All three answers were cut off even at 128k.

RSI and the native agents hit the same rules but recover by retrying. The single run with one rule repair gives the single run that one chance: it sends back only the rejection message, never a result. Per-split inputs

{{INV_NUMBERS}}

References are computed as follows:

  • 1-D Burgers: pseudospectral ETDRK4.
  • Darcy: finite volumes on an 8× refined grid.
  • Poisson and Helmholtz: sine series.
  • Navier–Stokes and Kolmogorov: integrating-factor RK4.
  • Allen–Cahn, 2-D Burgers and ADR: pseudospectral RK4.
  • 4-D elliptic: 63⁴ finite volumes.
  • Linear convection–diffusion: closed form.

The tolerance is at least 5× the reference's own error. That error is at most 3.5e-4 for every family except the 4-D one, whose reference error of about 1 % sets its 5 % tolerance.

Settings

Scoring (all suites)

The returned solution is linearly interpolated onto a uniform evaluation grid and compared with the exact or reference solution, using trapezoidal space-time and final-time relative L2. A case passes when all of these hold:

  • both relative L2 errors are within the tolerance;
  • initial and boundary values hold to 1e-10;
  • the solve fits the time limit (wall and CPU, including start-up) and the memory limit.

The reported class and coefficients are scored separately and never gate a case.

Harness and agent settings

ItemSetting
Models (Amazon Bedrock)Claude Opus 5.5, GPT-5.5, GPT-6.1, Claude Sonnet 4.5, GPT-OSS-120B. Output cap 64k tokens for Opus (32k for the others in the 6-round runs). The single runs of Opus use its 128k maximum, because at 64k its answer was cut off.
RSI roundEach round the model proposes the full program, or patches under v2. The candidate first passes a training self-test, with up to 3 attempts per round, and is then sent to the validation gate. Only the last 6 rounds of history are replayed.
Validation gateA candidate is accepted when all of these hold:
  • no execution, IC/BC or resource failure;
  • macro relative L2 drops by more than 0.5 %;
  • no class mean rises more than 5 % and no class pass rate drops;
  • no case's space-time or final-time error rises more than 25 %.
Under v2, a candidate that changes only class parts is gated per part, on the validation cases routed to that part.
Matched studies (18 and 20 Oct, v2 on 20 Oct)3 independent runs per configuration, a 2 h wall-clock budget, a $25 model-spending cap and 30 gated validation submissions. Each arm runs on its own dedicated CPU core of an H100 node. The single run is one request.
Earlier runs (16 and 17 Oct)RSI either ran 6 rounds with 2 continuation rounds, or ran for 2 h on concurrent pinned cores with at most 200 rounds.
Native agentsClaude Code with Opus 5.5 and Codex with GPT-5.5 (reasoning effort medium) run in a sandbox with no web tools. They get the same task text and an evaluation service: unlimited training evaluations, at most 30 validation submissions through the same gate, and the last accepted solver as the result. A run stops after two idle sessions.
Hidden casesThe sealed and fresh splits are never shown to any agent and are scored once, after freezing. Use the fresh splits, test3 and inventory_test2, for any further development decision. The earlier sealed splits have been inspected.
